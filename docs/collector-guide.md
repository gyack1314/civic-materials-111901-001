# 采集服务操作说明

低碳公开资料采集服务（`collector` 包）按来源契约调度访问：沿授权入口发现文件、
保存原始响应、回报每个专题收到了什么、还有哪些链接未取得。资料用于后续人工研究，
不计算低碳得分。

## 组成

| 部分 | 说明 |
| --- | --- |
| `python -m collector serve` | 采集服务，持续调度直到无待办（可用 `--max-idle` 退出） |
| `python -m collector add/cancel` | 资料组新增、取消城市专题（服务运行中也可执行） |
| `python -m collector status/report` | 专题收集状态、原件目录 |
| `python -m collector retry-refused/refresh-robots` | 来源拒绝后的复查手段 |
| 状态目录（默认 `./collector-state`） | SQLite 状态库 + `documents/` 原件 + `staging/` 暂存 + `report/` 报告 |

状态目录是采集端自己的持久记录，中断后用同一目录重启即可继续；
来源进程重启会清空其演练状态，采集端检测到来源时钟回退后会按来源当前状态重新对齐。

## 一次完整演练

```bash
# 1. 启动本地来源（另一个终端）
python -m source.server --port 8765

# 2. 登记城市专题，启动采集服务
python -m collector add 滨江 临港
python -m collector serve --poll 0.5 &

# 3. 演练时钟只由来源控制接口推进；等待额度时不必真实等待
curl -XPOST http://127.0.0.1:8765/__admin/advance -d '{"seconds":10}'

# 4. 查看各专题收到了什么、还缺什么
python -m collector status

# 5. 生成原件目录与专题状态（写入 collector-state/report/）
python -m collector report
```

调整访问政策（如阶段 1 市站 robots 禁止 `/files/`）：

```bash
curl -XPOST http://127.0.0.1:8765/__admin/advance -d '{"seconds":0,"phase":1}'
```

回查来源实际收到的请求（核对访问是否先于授权、是否超额）：

```bash
curl http://127.0.0.1:8765/__admin/log
```

## 调度规则（与来源契约对应）

- **额度按站点组记账**。`/policies` 公布的站点组（如市站组 `shared-city`、文件站组
  `files`）共享访问身份；HTML 页面、文件下载、转址后的一跳都按实际目标计入对应组。
  每次访问先写入本地台账再发请求，多个采集进程共用同一状态目录也不会一起触发封禁。
- **组间互不影响**。一个站冷却或等待只暂停该组，其他城市的专题照常推进。
- **robots 先判后发**。任何产品访问（含转址后的新地址）都先按目标主机的 robots
  决定能否继续，禁止的路径直接记为"来源拒绝"，不会先发出请求再补记拒绝。
  robots 缓存按来源时钟校验，时钟推进后自动重新确认政策。
- **Retry-After 整组冷却**。来源返回 429 时，共享该访问身份的所有请求都等到
  冷却截止时钟；冷却到期不等于 robots 禁止的路径重新获准。
- **新专题优先获得首次机会**。按"已获访问次数少者优先、同等时新增专题优先、
  再按发现先后"排序，等待中的旧链接不会长期挡住后来新增的专题。
- **共享原件只取一次**。同一原件被几个专题引用时共享已取得的字节，
  每个专题的来源关系都保留在原件目录中。
- **取消不虚报**。取消的专题不再促成新访问；仍在等待同一原件的其他专题继续；
  已经开始的传输如实继续完成，取消结果会分别报告"停止促成"与"传输中继续"的数量。

## 专题状态与处置

`status`/`report` 把未取得链接分成不同情况，资料员据此决定：

| 情况 | 含义 | 建议处置 |
| --- | --- | --- |
| 额度等待（冷却/窗口至时钟 N） | 站点组在冷却或窗口已满 | 继续等待，到期自动继续 |
| 排队中 | 当前可发，等调度轮次 | 继续等待 |
| 传输中 | 传输已开始 | 等待完成；取消不会虚报它 |
| 来源拒绝（robots 禁止） | 目标路径被 robots 禁止 | 改入口，或政策调整后 `retry-refused` |
| 来源拒绝（HTTP 4xx） | 来源明确拒绝 | 人工处理；确认后可 `retry-refused --include-failed` |
| 正文已取得尚未登记 | 中断时正文已取回未登记 | 重启服务自动补登记，不会重复下载 |

## 中断与恢复

- 用同一状态目录重启 `serve` 即继续处理未完成的专题。
- 仍有效的来源冷却、额度台账不会丢失；已保存的原件不会重复下载；
  只见过链接的地址仍是"待访问"，不会被当成已取得。
- 来源进程重启后其演练状态清空，采集端检测到来源时钟回退时，
  以来源当前状态为准重置台账与冷却（来源自己已不再执行那些限制）。

## 验证

```bash
python -m unittest discover -s tests -v
```

`tests/test_collector.py` 用来源的可回查记录验证：额度窗口与间隔、共同原件只取一次、
robots 先判后发、Retry-After 整组冷却且重启后仍有效、新专题优先、取消不虚报、
暂存正文补登记、来源重启后按来源状态对齐。
